# Техническая спецификация — TODO REST API

Статус: согласовано, готово к реализации
Дата: 2026-08-14

## 1. Scope

Backend REST API для управления задачами (TODO) в **single-user** режиме, без аутентификации. CRUD-операции и получение списка задач. Хранилище — SQLite. Стек — FastAPI + SQLAlchemy, тесты — pytest. Docker, PostgreSQL, Alembic на данном этапе не используются.

## 2. Functional requirements

- **FR1.** Создание задачи: `title` обязателен, `description` опционален, `status` опционален (по умолчанию `todo`).
- **FR2.** Получение списка всех задач (без пагинации и фильтрации).
- **FR3.** Получение одной задачи по `id` (UUID).
- **FR4.** Частичное обновление задачи (`PATCH`).
- **FR5.** Удаление задачи.
- **FR6.** `status` ограничен значениями: `todo`, `in_progress`, `done`.

## 3. Non-functional requirements

- **NFR1.** Приложение запускается локально без Docker (`uvicorn` напрямую).
- **NFR2.** Хранилище — SQLite, данные сохраняются между перезапусками.
- **NFR3.** Аутентификация/авторизация отсутствуют.
- **NFR4.** Валидация входных данных на уровне API (обязательность `title`, длина `title` 1–200 символов, допустимые значения `status`).
- **NFR5.** Схема БД создаётся автоматически при старте приложения (`Base.metadata.create_all()`), без миграционного инструмента.
- **NFR6.** Основные сценарии покрыты автотестами pytest.
- **NFR7.** Автоматическая документация API доступна по `/docs` (стандартное поведение FastAPI).

## 4. API contract

Базовый префикс: **`/api/v1`**

| Метод | Путь | Тело запроса | Успешный ответ |
|---|---|---|---|
| `POST` | `/api/v1/tasks` | `title` (обязательно), `description` (опционально), `status` (опционально, default `todo`) | `201 Created`, объект `Task` |
| `GET` | `/api/v1/tasks` | — | `200 OK`, массив `Task` |
| `GET` | `/api/v1/tasks/{id}` | — | `200 OK`, объект `Task` |
| `PATCH` | `/api/v1/tasks/{id}` | любое подмножество из `title`, `description`, `status` | `200 OK`, обновлённый объект `Task` |
| `DELETE` | `/api/v1/tasks/{id}` | — | `204 No Content` |

Пагинация и фильтрация — не реализуются на этом этапе (см. раздел 9).

## 5. Data model

### `Task`

| Поле | Тип | Ограничения |
|---|---|---|
| `id` | UUID | Генерируется автоматически, первичный ключ |
| `title` | string | Обязательное, длина 1–200 символов |
| `description` | string \| null | Опциональное |
| `status` | enum: `todo` \| `in_progress` \| `done` | Опциональное при создании, default `todo` |
| `created_at` | datetime | Устанавливается автоматически при создании, неизменяемо |
| `updated_at` | datetime | Обновляется автоматически при любом изменении задачи; гарантированно строго больше предыдущего значения после каждого успешного изменения (см. раздел 8) |

## 6. Error handling

Стандартный формат ошибок FastAPI (без кастомизации):

| Код | Ситуация | Формат тела |
|---|---|---|
| `404 Not Found` | Задача с указанным `id` не найдена | `{"detail": "Not Found"}` (или аналогичное сообщение) |
| `422 Unprocessable Entity` | Ошибка валидации (пустой/слишком длинный `title`, недопустимый `status`, невалидный UUID в пути) | стандартная структура ошибок валидации Pydantic/FastAPI |
| `500 Internal Server Error` | Необработанная серверная ошибка | стандартный ответ FastAPI |

## 8. Acceptance criteria

- Реализованы эндпоинты `POST/GET/GET{id}/PATCH/DELETE` по контракту из раздела 4.
- `id` генерируется как UUID при создании задачи.
- Создание задачи без `status` устанавливает `status = todo`.
- Создание задачи без `title` или с `title` длиннее 200 / короче 1 символа возвращает `422`.
- `PATCH` позволяет обновить любое подмножество полей (`title`, `description`, `status`), не требуя полного тела.
- `created_at` не изменяется после создания.
- `updated_at` строго больше предыдущего значения после каждого успешного изменения задачи (`PATCH`) — в том числе если системные часы не успели измениться между операциями (гарантия обеспечивается на уровне приложения, а не полагается на разрешение часов ОС).
- Запрос к несуществующему `id` (`GET`/`PATCH`/`DELETE`) возвращает `404`.
- Данные сохраняются в SQLite-файле и доступны после перезапуска приложения.
- Таблицы создаются автоматически при старте приложения без ручных миграций.
- Автотесты pytest покрывают: создание, список, получение по id, частичное обновление, удаление, 404-кейс, ошибку валидации `title`.
- Документация API доступна по `/docs`.
- Приложение запускается локально через `uvicorn` без Docker.

## 9. Explicitly out of scope

- Аутентификация и авторизация.
- Поддержка нескольких пользователей.
- Поиск по задачам.
- Пагинация списка задач.
- Фильтрация списка задач.
- Теги/категории, приоритеты, дедлайны.
- Soft delete, история/аудит изменений.
- Метод `PUT` (полная замена ресурса) — используется только `PATCH`.
- Миграции схемы БД (Alembic).
- Контейнеризация (Docker).
- PostgreSQL и другие СУБД, кроме SQLite.
